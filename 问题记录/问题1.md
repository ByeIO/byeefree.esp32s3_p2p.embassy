## 回答
根据你的错误信息和build.rs配置，链接器无法找到`link-esp32s3.x`等链接脚本文件。以下是修正方案及实现原理：

---

### **问题分析**
错误关键信息：
```sh
xtensa-esp-elf/bin/ld: cannot open linker script file link-esp32s3.x: No such file or directory
```
表明链接器在默认搜索路径中找不到链接脚本文件。虽然你的`linkall.x`和`rom_functions.x`与`build.rs`同级，但Rust/Cargo的编译工作目录可能与项目根目录不同，导致相对路径失效。

---

### **解决方案**
需要修改`build.rs`，确保链接脚本的 **绝对路径** 能被正确传递给链接器：

#### **1. 获取项目根目录路径**
在`build.rs`中通过`CARGO_MANIFEST_DIR`环境变量获取项目根目录：
```rust
use std::env;
use std::path::PathBuf;

fn main() {
    // 获取项目根目录绝对路径
    let manifest_dir = PathBuf::from(env::var("CARGO_MANIFEST_DIR").unwrap());
    
    // 构建链接脚本的完整路径
    let linkall_path = manifest_dir.join("linkall.x");
    let rom_functions_path = manifest_dir.join("rom_functions.x");
    
    // 输出链接参数（带完整路径）
    println!("cargo:rustc-link-arg-bins=-T{}", linkall_path.display());
    println!("cargo:rustc-link-arg-bins=-T{}", rom_functions_path.display());
}
```

#### **2. 验证文件位置**
确保`linkall.x`和`rom_functions.x`文件确实位于项目根目录（与`Cargo.toml`同级）。若文件在其他目录（如`ld/`子目录），需调整路径：
```rust
let linkall_path = manifest_dir.join("ld/linkall.x"); // 假设在ld目录下
```

#### **3. 补充说明**
- **环境变量**：`CARGO_MANIFEST_DIR`是Cargo自动设置的环境变量，指向`Cargo.toml`所在目录[22](@ref)。
- **跨平台兼容性**：`PathBuf::join`和`display()`方法会自动处理路径分隔符，确保Windows/macOS/Linux兼容[21](@ref)。
- **调试输出**：编译时可通过`cargo build -v`查看最终传递给链接器的完整路径是否正确。

---

### **扩展建议**
若问题仍未解决，可进一步排查：
1. **检查文件权限**：确保链接脚本文件可读。
2. **完整清理编译缓存**：运行`cargo clean`后重新编译。
3. **ESP-IDF配置**：确认是否需额外配置ESP32-S3的链接脚本（参考ESP-IDF文档中关于`-T`参数的使用）[49](@ref)。

---

通过上述修正，链接器将能正确找到脚本文件，解决`No such file or directory`错误。
